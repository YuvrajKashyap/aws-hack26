# Original offline simulation

All three JSON fixtures were authored for this public demo. They contain no downloaded datasets, workshop kit material, manuals, credentials, or account information. Local use is authorized by the implementation request; importing these files into a workshop account still requires organizer approval.

The fictional press has four samples at one-minute intervals. Temperature is Celsius, vibration is mm/s RMS, lubricant condition is a fictional 0–100 health index displayed as percent, and energy is kWh consumed during each preceding one-minute interval. Energy is explicitly simulated interval energy, not power mislabeled as energy. Each energy interval ends at its sample timestamp. The window describes sample endpoints, not the entire energy integration period. No energy conversion from power is performed.

The illustrative rule uses the last sample in a complete, ordered window: temperature >= 80 C, energy >= 0.65 kWh/interval, vibration >= 4.5 mm/s, and lubricant <= 60 percent each contribute 25 points. Zero is normal; 25–49 is watch; 50–100 is high. These thresholds are authored story mechanics, not validated industrial limits. All four channels must have at least two samples, valid units, in-window timestamps, increasing timestamps, and a final reading no more than 60 seconds before the replay end. Freshness is relative to the fixture end, not today's clock. Any quality issue or unsupported source/asset causes abstention, never imputation.

The supported simulation domain is temperature -20 to 200 C, energy 0 to 10 kWh/interval, vibration 0 to 100 mm/s, lubricant 0 to 100 percent. Fahrenheit is normalized with (F - 32) * 5/9 and Wh with /1000; original values remain inspectable. Unknown fields (including classifier target labels), unknown channels, nonfinite values, timezone-naive dates, and incompatible units are rejected. Out-of-domain, stale, duplicate/out-of-order, and missing samples remain visible and make risk unknown.

SIM-RULE-1 is an original fictional rule: a high band with both elevated temperature and vibration permits a simulated one-hour bearing inspection reservation, using SIM-BEARING-01 and a fixed sandbox slot. Other elevated combinations require human review. Normal needs no work order. Unknown data always requires review. This is not a manufacturer procedure or proof that replacement is necessary.

Bedrock output is restricted to a JSON list of known evidence IDs. The adapter may prioritize existing observations; it cannot introduce free prose, a part, score, useful-life estimate, or tool call. The renderer uses only validated local facts, always includes breached channels and uncertainty, and falls back if output is invalid. This deliberate limitation trades language flexibility for inspectable grounding. No manual text is executed or sent as instructions.

SQLite reserves inventory and a slot within BEGIN IMMEDIATE. The idempotency key derives from asset, content-addressed assessment and policy version. Replaying the same window returns the same result, including a review result. Review conflicts are terminal for that key; changing inventory alone does not silently retry an already reviewed action. A future explicit approval/retry workflow should version the action and be reviewed separately.
